Diagnosis: DNS resolution failure

A likely cause, not a certain one

What was measured

  • Router and public IP addresses respond normally
  • The configured DNS server did not answer any lookup

Probable cause

Your connection works, but the DNS server your device uses is not answering. This points to a resolver or DNS settings problem.

Not verified

Whether a VPN or filtering rule is blocking DNS. Router logs were not checked.

Recommended next step

Compare your configured DNS server against a known working one, check VPN and filtering settings, then run the test again.

How results are read

These are likely explanations. A router may block some tests and still pass normal traffic.

What the tests show Likely explanation Next action
Adapter disconnected Physical link or Wi-Fi connection failure Inspect adapter and connection
DHCP failed, no valid IP DHCP or local configuration issue Inspect lease and DHCP server
Gateway reachable, external IP fails WAN, routing, firewall, or upstream issue Check WAN state and trace the path
External IP works, DNS fails Resolver or DNS configuration issue Compare DNS servers
Only one website fails Website, routing, TLS, or application issue Test that domain and protocol
High local latency Wi-Fi congestion, poor signal, or heavy LAN traffic Compare wired and wireless tests
Good idle latency, severe latency under load Queueing (bufferbloat) Run loaded-latency tests
Intermittent packet loss Wireless interference, failing link, or upstream instability Compare results over time
